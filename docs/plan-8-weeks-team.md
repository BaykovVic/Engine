# Sky Engine: план создания с нуля — 8 недель, команда 4–5 человек

План восстановлен из фактически пройденного пути разработки: порядок работ,
зависимости и риски здесь не теоретические, а подтверждённые практикой.

## Состав команды

| Роль | Зона | Стек |
|---|---|---|
| **E1 — Ядро** (тимлид) | Модули object/component/scene/ecs, сериализация (SKYB + миграции), undo-система, project | C++20 |
| **E2 — Рендеринг** | Vulkan-бэкенд (offscreen + swapchain), viewport bridge, PBR/материалы, тени, terrain-рендер | C++20, Vulkan |
| **E3 — Редактор** | Avalonia-шелл, докинг, все панели, interop-слой (P/Invoke), UX-паритет с эталонным дизайном | C#/.NET 8, Avalonia |
| **E4 — Рантайм** | Физика, .NET-хостинг скриптов (hostfxr), player, input, платформенный слой (X11/Cocoa) | C++20, .NET hosting |
| **E5 — Пайплайн/QA** *(опционально)* | CI, тестовая инфраструктура, ассет-импортеры (PNG/OBJ/FBX/glTF), VFS, демо-контент | C++, CI |

При команде из 4 человек обязанности E5 распределяются: CI → E1,
импортеры/VFS → E4, демо-контент → E3. Это удлиняет M3–M4 примерно на неделю —
закладывайте её из буфера.

## Архитектурные решения — зафиксировать в первые 3 дня

Эти решения определили всю траекторию; менять их позже дорого:

1. **Qt-free ядро + C ABI мост.** Движок и «редакторский контекст»
   (EditorContext) не знают про UI-фреймворк. Редактор общается с движком
   только через плоский C ABI (`sky_editor_*`), который загружается в .NET
   через P/Invoke. Это же даёт бесплатный headless-доступ для тестов.
2. **Контракты модулей.** Каждый модуль — интерфейсы (IObjectFactory,
   IPhysicsQueryService, IScriptHost…) + одна фабрика. Никакого владения
   чужим состоянием; синхронизации (physics↔object, ecs↔object) — явные.
3. **Верификация headless с нулевого дня.** Vulkan на Mesa lavapipe, X11 под
   Xvfb, скриншоты как артефакты, `--screenshot`-режим у редактора. Каждая
   визуальная фича проверяется скриншотом, каждая логическая — ctest.
4. **Бинарная сериализация с версией схемы** (SKYB) + forward-миграции с
   первого формата.
5. **Скриптинг через hostfxr**, а не Mono/embedding: reverse-API как таблица
   cdecl-указателей, managed-энтрипоинты через UnmanagedCallersOnly.
   Таблица API — append-only (обе стороны декларируют layout).

## Вехи

- **M1 (конец нед. 2) — «Первый кадр»**: демо-сцена рендерится в док-панели
  редактора; Hierarchy живая; ctest + CI зелёные.
- **M2 (конец нед. 4) — «Авторинг»**: гизмо (move/rotate/scale), Inspector
  с полями компонентов, Undo/Redo, Save/Open сцены, Play/Pause/Stop с
  физикой и восстановлением сцены.
- **M3 (конец нед. 6) — «Замкнутые петли»**: standalone-player запускает
  авторскую сцену; вертикальный срез скриптинга (C#-класс крутит объект,
  Debug.Log в Console, Time/Input); импорт моделей + drag-drop.
- **M4 (конец нед. 8) — «Продукт»**: пользовательские скрипты из
  Assets/Scripts с сериализуемыми полями, префабы, тени, terrain-инструменты,
  мини-игра-демка.

## Понедельный план

### Неделя 1 — фундамент (все)
- **E1**: скелет репозитория, CMake-каркас модулей, core (math/handles/log),
  object world (иерархия+трансформы), component world (дескрипторы + поля
  как variant-map — это позже бесплатно даст сериализацию, undo и поля
  скриптов).
- **E2**: Vulkan instance/device/offscreen-таргет, треугольник + readback в
  PNG (это фундамент всей верификации).
- **E3**: Avalonia-проект, докинг (Dock.Avalonia), заглушки панелей,
  hello-bridge: P/Invoke вызывает `sky_editor_create` из .so.
- **E4**: физика v1 (AABB-боксы, гравитация, heightfield-резолв), контракт
  physics↔object sync.
- **E5**: CI с первого дня: сборка C++ **и** dotnet-сборка редактора
  (C#-поломки без CI проходят молча — проверено), ctest под Xvfb,
  скриншот-артефакт.
- **Все**: полдня на фиксацию контрактов модулей (см. выше).

### Неделя 2 — первый кадр (M1)
- **E1**: scene world (роуты, авторинг-сервисы), демо-сцена в EditorContext.
- **E2**: меши/пуш-константы/UBO, камера, свет (directional+point), PBR v1;
  viewport bridge: FrameBuilder обходит сцену → рендер-команды.
- **E3**: панель-вьюпорт (offscreen → WriteableBitmap), Hierarchy на живых
  данных через ABI (root_count/child_at/name), orbit/pan/zoom камеры.
- **E4**: player-скелет: то же ядро + окно (X11) + swapchain; `--headless`.
- **E5**: заготовка `--screenshot`-режима редактора (headless Avalonia);
  первые юнит-тесты модулей.

### Недели 3–4 — авторинг (M2)
- **E1**: undo-стек и команды (transform/field/create/delete/reparent —
  снапшот поддерева объекта сразу lossless: имя+трансформ+все поля
  компонентов+дети; это переиспользуется трижды: undo, префабы, сцены);
  SKYB save/load; rename/duplicate/reparent.
- **E2**: пикинг (луч в сцену), проекция world→screen для гизмо, Game-вью
  через Main Camera (второй offscreen), скайбокс.
- **E3**: гизмо move/rotate/scale + тулбар с хоткеями Q/W/E/R; Inspector:
  data-driven поля компонентов (string/float/bool/Vec3 + ссылки-пикеры),
  Add/Remove Component, rename; Console/Materials/Packages на живых данных.
- **E4**: play mode: snapshot трансформов на входе, физика тикает, restore
  на выходе (+ re-seat тел с нулевой скоростью); input-события из UI в
  движок (портируемые кей-коды — общий enum с C#).
- **E5**: импортеры OBJ + PNG, asset database, VFS (`assets://`);
  bridge-тесты на каждую группу ABI.

**Ворота M2**: сцену можно собрать руками, сохранить, открыть, сыграть,
выйти — и она вернулась в исходное состояние. Всё покрыто bridge-тестами.

### Недели 5–6 — замкнутые петли (M3)
- **E1**: чистка границы EditorContext (что уедет в player, а что нет),
  scene-формат: физика восстанавливается из компонентов.
- **E2**: текстуры/PBR-слоты в материалах, процедурные примитивы
  (sphere/plane), стат-оверлей.
- **E3**: пикер мешей как в Unity (ComboBox по ассетам), drag-drop модели
  из Project в Hierarchy, scene-гизмо в углу вьюпорта, 2D-режим.
- **E4**: **скриптинг — критический путь**: hostfxr-хост, bootstrap-сборка,
  ScriptComponent (аналог MonoBehaviour), lifecycle-события, reverse-API
  (SetLocalPosition/Euler/Scale), sky.script компонент, тик в play-цикле;
  затем Debug.Log→Console, Time, Input.GetKey.
- **E5**: FBX/glTF-импортеры; player запускает `.skybox` (петля
  «сохранил → запустил в билде»); смоук плеера в CI.

**Ворота M3**: C#-скрипт, повешенный на объект в редакторе, работает и в
Play редактора, и в standalone-player. Проверка точная: 90°/с × 1 с = 45°.

### Недели 7–8 — продукт (M4)
- **E1**: префабы (.skyprefab поверх готового снапшота — инфраструктура уже
  есть с недели 3), терраин-хайтфилд в сцену.
- **E2**: shadow mapping (depth-only pass + PCF) — самый большой визуальный
  скачок на единицу усилий; полиш освещения.
- **E3**: пикер классов скриптов в Inspector (рефлексия), сериализуемые поля
  скриптов (публичные поля класса → строки Inspector, персист в компоненте);
  UX-полиш по эталону.
- **E4**: пользовательские сборки из Assets/Scripts (генерируемый csproj +
  dotnet build, collectible AssemblyLoadContext → перезагрузка между
  Play-сессиями); игровой API: Instantiate/Destroy/velocity/raycast.
- **E5**: мини-игра-демка на движке (dogfood — она вскрывает дыры API лучше
  любого ревью), нагрузочные прогоны тестов, документация.

**Вторая половина недели 8 — буфер.** По опыту он уходит целиком: на
стабилизацию (гонки в тестах), полиш и хвосты M4.

## Критический путь

```
C ABI мост ──► всё в редакторе (E3 блокируется без него — E1 отдаёт ABI инкрементально, с недели 1)
Offscreen-рендер ──► вьюпорт ──► гизмо/пикинг
Play mode ──► скриптинг ──► пользовательские скрипты
Снапшот объекта (нед. 3) ──► undo delete ──► префабы (нед. 7, почти бесплатно)
```

Скриптинг — самый длинный хвост зависимостей: не начинать его позже
недели 5.

## Риски (все — из реальной практики)

| Риск | Митигация |
|---|---|
| Тихие поломки C#-сборки (dotnet run на устаревшем бинаре) | CI собирает редактор; локальное правило «проверь 0 Errors до запуска» |
| Дрейф таблиц API через ABI (native struct ≠ managed struct) | Append-only таблицы; bridge-тест на каждую функцию в день её добавления |
| Гонки в тестах через общие temp-каталоги | Изоляция per-binary с первого теста; тяжёлые тесты — RUN_SERIAL |
| Vulkan в CI | lavapipe + Xvfb с недели 1, не «потом» |
| Демо-фикстуры становятся кодом (пустой .cs в Assets → компилится как настоящий) | Фикстуры не кладутся в каталоги с семантикой |
| Скоуп-крип редактора (докинг, темы, полиш съедают недели) | Тайм-бокс UX-полиша; функционал панелей раньше пиксель-паритета |
| Раскоординация слоёв (движок ждёт UI и наоборот) | Вертикальные срезы: фича = движок+ABI+UI+тест одним PR |

## Практики

- **Вертикальные срезы, не горизонтальные слои.** Один PR проводит фичу
  насквозь: движок → ABI → UI → тест → (скриншот). Никогда «сделаем весь
  рендер, потом весь UI».
- **Каждая фича верифицируется в день написания**: ctest — логика,
  headless-скриншот — визуал, точные численные проверки для симуляции
  (45° за секунду, +3.0 м за секунду зажатой W).
- **Backlog-документ в репозитории** (docs/backlog.md), обновляется в тех же
  PR — единственный источник правды «что осталось».
- **Демо-сцена — полигон**: в ней с первого дня есть по экземпляру всего
  (свет обоих типов, физика, меш из импорта, скрипт) — любой прогон
  редактора/плеера/теста прогоняет весь стек.
